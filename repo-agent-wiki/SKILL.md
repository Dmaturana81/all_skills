# Repo Agent Wiki Generator

Build a **layered context wiki** so coding agents navigate by progressive disclosure instead of loading monolithic `PROJECT.md` or grepping the whole repo.

## When this applies

- New repo needs agent-oriented documentation
- Existing docs are scattered or too large for session context
- User wants the same structure as `wiki_<project>/` (L0 boot → L4 reference)

## Before you start — confirm with user

| Decision | Default | Notes |
|----------|---------|-------|
| Folder name | `wiki_<short-name>/` at repo root | e.g. `wiki_mjauto` |
| Language | English | Or match team preference |
| Gitignore wiki | Ask | Often yes for local-only wikis |
| Domain count | 5–8 | Derived from repo, not fixed at 7 |
| Cursor rule | Draft only in `meta/DRAFT_CURSOR_RULE.md` | Install only if user asks |
| Phases | Scaffold first, fill second | Unless user wants one-shot fill |

## Layer model

| Layer | Path | Budget | Content type |
|-------|------|--------|--------------|
| **L0** | `00_BOOT.md` | ~200 tokens | Identity, stack, mandatory agent rules |
| **L1** | `01_MAP.md` | ~700 tokens | System map, domain router table |
| **L2** | `domains/*.md` | ~1k each | One bounded context per file |
| **L3** | `topics/*.md` | On demand | Deep dives (one concern each) |
| **L4** | `reference/*.md` | Lookup only | Tables — no narrative |
| **meta** | `meta/` | — | Protocol, changelog, cursor rule draft |

Full spec: [references/layer-spec.md](references/layer-spec.md)

## Workflow

### Phase 0 — Discover the repository

1. Read `PROJECT.md`, `README.md`, `docs/`, package manifests, `docker-compose*`, main entry points.
2. Identify **bounded contexts**: services, packages, layers, deploy units.
3. Map **cross-cutting** areas: always consider `api` (or `frontend`), `database`, `infra` if they exist.
4. List existing docs to **migrate** (not duplicate) — record paths in domain/topic frontmatter as `migrate_from`.
5. Note env vars, queues, endpoints, schemas from **code** (not guesses).

Checklist: [references/discovery.md](references/discovery.md)

### Phase 1 — Scaffold

Create the full tree even if bodies are stubs:

```
wiki_<name>/
├── README.md
├── 00_BOOT.md
├── 01_MAP.md
├── domains/          # one .md per discovered domain
├── topics/
│   └── README.md     # index + planned topics
├── reference/
│   ├── file-map.md
│   ├── env-vars.md
│   ├── api-endpoints.md   # omit if no HTTP API
│   ├── db-schema.md       # omit if no DB
│   ├── queues.md          # omit if no messaging
│   └── docker-images.md   # omit if no containers
└── meta/
    ├── AGENT_PROTOCOL.md
    ├── CHANGELOG.md
    ├── DRAFT_CURSOR_RULE.md
    └── INDEX.md          # hub for planning + evidence (created lazily, see below)
```

**Planning and evidence live under `meta/`, one folder per kind, each with its own `INDEX.md`, all linked from the `meta/INDEX.md` hub.** Other wiki skills create them lazily; this skill only defines the shape:

| Folder | Written by | Holds |
|--------|------------|-------|
| `meta/wayfinding/<effort>/` | `/wayfinder-wiki` | Maps of decision tickets for foggy efforts (indexes generated by its script) |
| `meta/sdlc-artifacts/<effort>/` | `/grilling-wiki`, `/to-spec-wiki` | intent, spec, plan, test, deploy, maintain |
| `meta/research/` | `/research-wiki` | Cited research notes |
| `meta/prototypes/` | `/prototype-wiki` | Prototype verdicts and their branches |

When the first of these appears, `01_MAP.md` gets one router row: "Planning in flight, wayfinding, research, prototypes → `meta/INDEX.md`". Durable outcomes do not stay in `meta/`: terms go to L2 `## Language`, trade-offs to `topics/decisions/`, facts to L4.

- Every markdown file gets YAML frontmatter (`layer`, `scope`, `parent`, `read_when`, `code_paths`, `children`).
- L2 domains: responsibilities checklist, key paths, links to L3/L4, **"Do NOT read unless"** section.
- L3 topics: `status: stub`, `migrate_from`, outline with `- [ ]` items.
- L4 reference: table skeletons with `TODO — verify from <source file>`.

Tree + frontmatter templates: [references/scaffold-tree.md](references/scaffold-tree.md)

**Also:**
- Add `wiki_<name>/` to `.gitignore` if user wants local-only wiki.
- Do **not** install Cursor rule unless asked.

### Phase 2 — Fill (recommended order)

1. **L4 reference** — verify from code (`settings.py`, compose, CRUD DDL, routers).
2. **L3 topics** — migrate from richest module docs; one topic per narrow concern.
3. **L2 domains** — expand checklists; link filled topics; remove redundant prose.
4. **meta/CHANGELOG.md** — dated entries from git history or `PROJECT.md` recent changes.
5. **L0/L1** — only update routing tables and status banner; keep L0 stable.

Fill guide: [references/fill-workflow.md](references/fill-workflow.md)

### Phase 3 — Handoff

Summarize for user:
- Entry point: `wiki_<name>/00_BOOT.md`
- Domain list and what's filled vs stub
- Cursor rule draft location
- Suggested next topics to fill

## Anti–context-rot rules (enforce in every wiki)

1. **L0 + L1 ≤ ~1k tokens combined** — permanent session tax.
2. **No prose in L4** — tables and links only.
3. **One canonical home** per topic — link legacy docs, don't copy wholesale.
4. **Max 2 domains per agent session** — state this in `AGENT_PROTOCOL.md`.
5. **Frontmatter `read_when`** — keyword list for routing without reading body.
6. **`code_paths`** in domains — prefer over repo-wide search.

## Domain discovery (any repo)

Do not blindly copy seven microservice names. Instead:

| Signal | Likely domain |
|--------|----------------|
| HTTP routers / controllers | `api` or `frontend` |
| ORM / migrations / CRUD | `database` |
| Docker / K8s / CI | `infra` |
| Separate worker or service dir | one domain per worker |
| Shared library | `shared` or fold into consumer domain |
| ML / extraction pipeline | `nlp`, `ml`, `inference`, etc. |

Aim for **5–8 domains**; merge tiny folders into parent domain.

## Updating an existing wiki

After code changes:
1. Append `meta/CHANGELOG.md`
2. Patch affected `reference/` or `domains/` page
3. Add L3 topic if new cross-cutting concern emerges, and list it in `topics/README.md`
4. If the change implements an effort, mark its spec in `meta/sdlc-artifacts/<effort>/` and update that folder's `INDEX.md`
5. Do not bloat `00_BOOT.md`
6. Run the validator

## Cursor rule draft

Use template: [assets/cursor-rule-template.md](assets/cursor-rule-template.md)

Replace `<WIKI_DIR>`, `<PROJECT_NAME>`, domain table. Save to `meta/DRAFT_CURSOR_RULE.md` only.

## Validation

Before finishing scaffold or fill pass:

- [ ] Every domain linked from `01_MAP.md` router table
- [ ] `topics/README.md` lists all L3 files with status
- [ ] `AGENT_PROTOCOL.md` decision tree covers all domains
- [ ] L4 pages cite `source:` in frontmatter
- [ ] No duplicate full API lists in domain files (link to `reference/api-endpoints.md`)
- [ ] `README.md` at wiki root explains layers and status
- [ ] Every planning folder under `meta/` has an `INDEX.md` listing its files, linked from `meta/INDEX.md`, which `01_MAP.md` links
- [ ] Every relative link resolves

Run [scripts/validate_wiki.py](scripts/validate_wiki.py) on the wiki folder; it checks all of the above except the protocol decision tree and L4 `source:`. If `meta/wayfinding/` exists, also run `wayfinder-wiki`'s `scripts/wayfinding.py check`.
